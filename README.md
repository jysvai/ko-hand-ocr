# ko-hand-ocr

한글·영문이 섞인 **손글씨 한 줄**을 읽는 작은 모델. Apache-2.0.

```
사진 한 장  ->  줄 자르기  ->  ko-hand-ocr  ->  "부서 : AI혁신TF"
```

- **31M 파라미터.** GPU 없이 CPU 에서 칸당 0.2초. 메모리 900MB.
- **자모 어휘 229개.** 음절 11,172자를 통째로 외우지 않는다. 학습에서 한 번도
  못 본 글자도 쓸 수 있다.
- **손글씨 데이터셋을 쓰지 않았다.** 디코더는 처음부터 학습했고 인코더는
  ImageNet ViT(Apache-2.0)다. 학습 그림은 손글씨 **글꼴**로 그때그때 그렸다.
  그래서 데이터셋 약관을 물려받지 않는다 → [PROVENANCE.md](PROVENANCE.md)

## 설치

```bash
pip install ko-hand-ocr
```

무게(가중치)는 따로다. 하나에 120MB 라 저장소에 안 넣는다.
[Releases](https://github.com/jysvai/ko-hand-ocr/releases) 에서 받아 풀면 된다.

| 받는 것 | 크기 | 무엇 |
|---|---|---|
| `ko-hand-ocr-v18.zip` | 120MB | 판 하나. 이것만으로 읽힌다. |
| `ko-hand-ocr-ensemble.zip` | 444MB | 판 넷. 더 정확하고 11배 느리다. |

## 쓰는 법

```python
from kohandocr.reader import Reader

reader = Reader("ko-hand-ocr-v18", device="cpu")

# 사진 한 장을 통째로. 줄 자르기까지 해 준다.
reader.read_photo(open("scan.jpg", "rb").read())
# -> ['보안점검표', '부서 : 데이터팀', '이름 : 홍서말']

# 이미 줄을 잘라 두었다면 그림을 바로 넘긴다. 묶음으로 넣어야 빠르다.
reader.read([cell_a, cell_b, cell_c])

# 후보 목록이 있으면 그 안에서만 고르게 가둘 수 있다.
reader.both([cell_b], options=["데이터팀", "AI혁신TF", "인재팀"])
# -> [{'text': '부서 : 데이더팀', 'constrained': '데이터팀', 'agrees': True}]
```

**가둔 결과만 믿으면 안 된다.** 가둬 놓았으니 모델은 반드시 목록 안의 값을
내놓는다. 목록에 없는 것이면 엉뚱한 답이 나오고, 그것만 보면 틀린 줄 모른다.
`agrees` 가 거짓이면 사람에게 넘겨야 한다.

### 여러 판으로 읽기

판마다 잘 읽는 칸이 엇갈린다. 같은 자료로 조금 더 학습했을 뿐인데 어떤 칸은
살고 어떤 칸은 죽는다 — 그 칸을 아슬아슬하게 읽고 있다는 뜻이다. 그래서 판을
여럿 두고 **여러 번 같게 나온 답**을 고른다.

```
받은폴더/
  config.json  vocab.json  model.safetensors
  also/
    v20b/  config.json  vocab.json  model.safetensors
    v19/   ...
```

`also/` 가 있으면 `Reader` 가 알아서 쓴다. 부르는 법은 그대로다.

확신도로 합치는 것은 재 봤고 **안 됐다** — 틀린 답을 더 확신하는 일이 있어서다.
그래서 확신도가 아니라 **서로 얼마나 닮았나**로 고른다.

## 속도와 사양 (실측)

GPU 가 필요 없다. 자모를 하나씩 차례로 뽑는 것이 병목이라 코어를 늘려도
별로 안 빨라지고, 반대로 **약한 PC 에서도 느려지지 않는다.**

| | 사진 한 장(3칸) | 칸당 | 메모리 |
|---|---|---|---|
| 판 하나, CPU 실 2개 | 0.63초 | 0.21초 | 888MB |
| 판 하나, CPU 실 8개 | 0.49초 | 0.16초 | 888MB |
| 판 넷, CPU | 6.5~7.3초 | 2.2초 | 1352MB |

## 얼마나 맞히나

| | 손글씨 사진 11장 | 가장 나쁜 장 | 안 배운 글씨체 |
|---|---|---|---|
| 판 하나 | 90.6% | 78.5% | 81.1% |
| 판 넷 | **93.3%** | **81.2%** | 84.6% |

자모 단위 닮음이고, 사진 한 장에 한 표다.

**이 숫자를 그대로 기대하면 안 된다.** 만든 사람의 사진 11장으로 잰 값이고
폭이 ±5%p 다. 남의 손씨에 더 가까운 값은 **'안 배운 글씨체' 쪽(84.6%)** 이다 —
학습에 한 번도 안 쓴 글꼴로만 시험한 것이라 흔들림이 절반이다(±2.5%p).

```bash
python tools/holdout.py <판폴더>     # 안 배운 글씨체로 재 본다. 글꼴만 있으면 된다.
```

## 학습

데이터를 굽지 않는다. 글월을 만들고 손글씨 글꼴로 그려서 **그때그때** 먹인다.
그래서 디스크에 학습 데이터가 남지 않고, 분포를 바꾸면 다음 걸음부터 바로 반영된다.

```bash
python tools/fetch_fonts.py                       # OFL 손글씨 글꼴을 받는다
python -m kohandocr.train --out runs/v1 \
       --steps 20000 --batch 40 --workers 3 --letters 128
```

글꼴 자리는 이 차례로 찾는다. **경로를 코드에 박지 않는다.**

1. `--fonts` 로 준 값
2. 환경 변수 `KOHAND_FONTS`
3. `~/.cache/ko-hand-ocr/fonts`

글꼴은 이 저장소에 들어 있지 않고 **재배포하지 않는다.** 나눔손글씨 109벌은
[clova.ai/handwriting](https://clova.ai/handwriting) 에서 받는다. 자세한 것은
[PROVENANCE.md](PROVENANCE.md).

합성이 실제 손글씨와 얼마나 닮았는지는 `kohandocr/measured.json` 에 적힌
실측 분포(잉크량, 밀도, 가로세로, 여백 등 아홉 가지)로 견준다.

```bash
python tools/match.py        # 과녁과 지금 합성을 나란히 본다
```

**오래 돌린다고 좋아지지 않는다.** 합성 분포를 바꾼 뒤에는 짧게 돌고 중간 판을
남겨서 골라야 한다(실측: 15,000걸음이 꼭짓점이고 30,000걸음은 오히려 내려갔다).

```bash
python tools/pick.py runs/v1-15000 runs/v1-30000    # 남긴 판들을 재서 고른다
```

## 아직 안 되는 것

- 표 안의 칸을 라벨과 값으로 갈라 주지 않는다. `read_photo` 는 줄까지만 자른다.
- 세로쓰기, 칸 병합은 다루지 않는다.
- 읽을 것이 없는 칸(칸 전체가 낙서인 것)도 무언가 읽어 낸다.

## 라이선스

Apache-2.0. 가중치도 같다. 학습에 쓴 글꼴의 라이선스는 가중치에 옮아붙지
않는다 — 가중치는 글자 모양의 저작물이 아니라 그림에서 배운 값이다.
근거는 [PROVENANCE.md](PROVENANCE.md) 에 부품별로 적어 두었다.
